# NovaHair Popup Analytics

## Runtime architecture

- Storefront events are generated by the popup theme assets and sent to `/apps/funnels/api/track`.
- Shopify App Proxy signs and forwards those requests to the Cloudflare Worker.
- The Worker validates the proxy signature, sanitizes the payload, and persists idempotent events in D1.
- Lead success is written only after the Worker finds the customer in Shopify Admin GraphQL with both popup tags and `SUBSCRIBED` email consent. The email is used transiently and is never stored in analytics.
- Purchases, net revenue, and discount usage come only from Shopify order webhooks. Popup qualification is carried in underscore-prefixed line-item properties.
- `/api/analytics/popup` queries D1 and is protected by Shopify App Bridge session-token authentication.
- `/admin/popup-analytics.html` is the embedded admin shell. It is `noindex`; without an authorized Shopify session its data API returns `401`.

## Counting rules

- The anonymous visitor ID persists in `localStorage`; a browser-tab session ID lives in `sessionStorage`.
- Eligible, view, email-start, consent, coupon reveal, continue, and close use deterministic keys per popup version, tab session, and page path.
- A force-open, rerender, duplicate listener, or reopen can resend the same semantic event, but D1's unique `eventKey` stores it once.
- Each valid submit click gets a numbered attempt. A retry is a new attempt.
- Successful Leads is unique by an HMAC-pseudonymized Shopify customer key and popup version.
- A popup purchase is one unique Shopify order carrying `_NOVA_EXIT_POPUP=1`; coupon orders are orders whose Shopify discount list contains the configured production coupon.

## Source of truth

| Metric | Source |
| --- | --- |
| Eligible, view, interactions, coupon reveal, continue, close | Signed storefront event persisted in D1 |
| Submit attempt and failure | Signed storefront event persisted in D1 |
| Successful lead | Shopify Admin customer confirmation, then D1 |
| Popup order and revenue | Shopify `orders/paid` / `orders/updated` webhook |
| Coupon order and revenue | Shopify order `discount_codes` |

## Production configuration

- Worker: `shopify-funnel-control`
- D1 binding: `DB`
- Popup version: `NOVAHAIR_POPUP_VERSION`
- Coupon code: `NOVAHAIR_POPUP_COUPON`
- Required secret aliases: `SHOPIFY_ADMIN_ACCESS_TOKEN`, `SHOPIFY_CLIENT_SECRET`, `SHOPIFY_WEBHOOK_SECRET`
- Migration: `migrations/0005_popup_analytics.sql`

Analytics is non-blocking. Failure to track or confirm analytics never prevents closing the popup or browsing the store; an unconfirmed lead restores the form and allows retry.

## Existing platform reconciliation

Draft PR `shopify-internal-funnel-app#4` contains a broader, staging-only TIGER popup platform with signed identity, campaign arbitration, and randomized `POPUP`/`HOLDOUT` assignment. Its safety flags intentionally disable production collection and rendering, and it is not the deployed Worker serving the current NovaHair popup.

This release recovers the existing deployed Cloudflare Worker source into Git and instruments the current NovaHair popup without activating the generic platform or changing popup targeting. The two systems must not both ingest the same production popup. A future migration can adopt PR #4's signed session and holdout contracts after the popup release owner approves a randomized no-popup group.

Current NovaHair reporting is verified attribution, not causal lift: it distinguishes eligible sessions from actual views and uses Shopify truth for leads and orders, but it does not claim incrementality against a randomized holdout.
