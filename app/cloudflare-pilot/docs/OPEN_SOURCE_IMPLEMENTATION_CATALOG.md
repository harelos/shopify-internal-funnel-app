# Open-source implementation catalog

Last reviewed: 2026-09-08

This catalog is the approved starting point for reusable patterns in Commerce OS. It is not permission to paste arbitrary repository code into production. Every adoption still requires a pinned version, license notice where required, local tests, security review, and a visual pass against the Commerce OS design tokens.

## Selection rules

- Prefer official Shopify and Cloudflare primitives for storefront, checkout, Worker, D1, queue, and workflow behavior.
- Prefer small patterns over importing an entire platform. Commerce OS already has authoritative ledgers and must not gain a second source of truth by accident.
- Never copy code whose license is unclear, copyleft, enterprise-only, or source-available without an explicit legal decision.
- Keep raw provider names, event keys, identifiers, and payloads behind drill-down views. Owner-facing screens use plain English.
- All imported UI is restyled through one Commerce OS token layer. No third-party default theme may become a second visual system.
- Every customer or order join must remain evidence-based. No library may infer an attribution link that the ledgers cannot prove.

## Implementation shortlist

The catalog changes the build order in only three practical ways:

1. **Checkout attribution now:** follow Shopify’s Web Pixel contract, and borrow Snowplow/Segment’s stable envelope and destination-isolation patterns. Do not add a new analytics platform.
2. **Experiments next:** retain our deterministic D1 allocator while adding GrowthBook-style preflight, explicit exposure, sample-ratio checks, and a clean lifecycle. Assignment must happen before the tested element paints.
3. **Support and operations later:** use Cloudflare Workflows/Queues only where retries and durable progress materially improve the existing cron. Use Chatwoot/Tremor/shadcn as information-architecture references while keeping one branded front end.

## Dependency admission checklist

Before any repository code or package enters production:

- Record the exact package/repository version and commit.
- Verify the license at that exact version and preserve required notices.
- Review transitive dependencies, install scripts, bundle impact, and known advisories.
- Reject code that requires secrets in the browser, broad origin matching, dynamic evaluation, or unsafe HTML injection.
- Add unit/integration tests for idempotency, retries, consent, PII redaction, and failure-open behavior where relevant.
- Verify desktop and Shopify embedded-mobile states using the existing app, not the source project’s screenshots.
- Add the decision and verification evidence to `COMMERCE_OS_EXECUTION_STATUS.md` before release.
