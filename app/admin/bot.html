Identity & placement

Trust rule: natural/humanized language is allowed, but the assistant must not falsely claim to be a human or falsely deny being AI when asked.

Brain / routing

Sales is the default route
Product, funnel and cart questions stay with the sales agent unless a higher-priority route applies.
Support specialist
Order status, delivery, refund and active service issues. Selling is blocked while an unresolved complaint is active.
Retention specialist
Returning/VIP customer with purchase intent or a relevant repeat-purchase opportunity.
Risk / dispute specialist
Chargeback or legal-risk conversation. Legal threats can require human escalation.
Security gate
Prompt injection, API extraction, off-topic abuse and scope violations run before all agents.
Routing precedence: Security → Risk → Support → Retention → Sales. The model can suggest intent but cannot override deterministic access/tool boundaries.

Sales playbook

The system stores compact principles and approved examples, not copied book text. Product truth and store policy outrank persuasion playbooks.

Offers & coupons

Fail closed: no unit economics = no automatic discount. The LLM never sees the coupon pool and cannot invent a code. A server tool allocates a code only after an approved offer authorization.

Models & experiments

Traffic is sticky per eligible visitor/conversation. All variants must total 100% and share the same knowledge, tools and offer policy for a fair comparison.

Traffic allocation: 100%

Core metrics: purchase conversion, assisted revenue, contribution profit, AI cost, profit after AI cost, latency p50/p95, handoff/error rate and sample size.

CRM & memory

Progressive profiling
Deliver value before asking for contact fields.
Email capture
Ask when it unlocks a real benefit such as saved recommendation, cart, coupon or order update.
Phone capture
Only for explicit callback/follow-up need or opted-in channel.
Automatic attribution
UTM/referrer/funnel context should be captured automatically rather than asked when already known.
CRM facts need provenance/confidence. Do not save guesses as facts, and do not proactively ask age unless a legitimate product/compliance need requires it.

Security & abuse controls

Least-privilege tools
Sales, Support, Retention and Risk receive different server-side tool allowlists.
No secrets in prompt/browser
System prompt is not a security boundary; API keys, margins and raw coupon inventory stay server-side.
Verified order access
Knowing an order number alone is not sufficient to expose customer/order details.
Cost / loop limits
Provider calls, tool loops and retries must have hard bounded budgets.
Configuration is staging-only. Nothing is injected into the storefront.
